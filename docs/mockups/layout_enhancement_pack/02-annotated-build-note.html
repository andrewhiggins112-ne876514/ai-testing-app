Build notes. Markers and acceptance bullets per area. Product UI is not part of this Studio pass.

How to read the markers

These attributes live on the mock HTML so a later Build slice can map acceptance checks. They are not a new product API.

  • data-layout-enhancement-pack stage root
  • data-lep-area settings, suites, plans-cases, plans-tabs, reports, documents, security, heal, manual, desktop, sandboxes
  • data-lep-empty one-line empty scan · data-lep-unfocused Select a row
  • data-lep-kbd keyboard note (Studio bar, do not ship the bar)
  • data-lep-scroll pane scroller · data-lep-sticky on the wire’s scan · data-lep-no-outer-scroll
  • data-lep-structure rail / tabs / no rail · data-lep-lexicon
  • data-lep-bool Show archived, case Enabled/Archived, Pause on fail
  • data-lep-sections Edit / Run / Quarantine / Known issue · data-lep-pin Save + Run
  • data-show Documents toolbar scope · data-lep-heal-confirm
  • data-lep-advanced Desktop and Sandboxes · data-lep-start-collapse · data-lep-dock
  • data-lep-filter Suites and Reports · data-lep-evidence="phase2"

Phase split

Phase 1 is structure craft on the shipped FR-UI-11 grammar: empty, keyboard, one scroll, sticky header, lexicon labels, Plans booleans and sections, Documents toolbar scope, Heal confirm copy, Manual focus chrome, toolbar filters, closed Advanced. Phase 2 is the evidence hint on Reports, Heal, and Manual only. Do not block Phase 1 on it.

Suggested epic (draft, not created): Layout enhancement pack — FR-UI-11 craft. One story per cluster below, each with a linked test ticket, after Designer accept and a Council pass on whether the keyboard line and the Phase 2 slot need spec text.

Do not edit in Design Studio

ui/desktop/index.html, ui/desktop/desktop.js, ui/desktop/desktop.css, desktop_app.py. Charter frame nodes stay out of this pack. Orb, home/chat, and App nav stay locked.
